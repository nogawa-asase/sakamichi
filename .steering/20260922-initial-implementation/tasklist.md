# 初回実装 タスクリスト

`design.md` の「4. 実装アプローチ」に従い、データが流れる順(環境構築→地図→補間→標高取得→計算→描画→仕上げ)
に実装する。各タスクの完了条件は `requirements.md` の受け入れ条件に対応する。

- [x] `package.json` を作成し、devDependenciesに `eslint`, `typescript` を追加
- [x] `npm scripts` に `lint`(`eslint .`)、`typecheck`(`tsc --noEmit`)を定義
- [x] `eslint.config.js` を作成(ES2015以降・ブラウザ環境・`sourceType: module`)
- [x] `tsconfig.json`(`checkJs: true`)を作成し、`js/`配下を型チェック対象にする
- [x] `.gitignore` に `node_modules/` を追加
- [x] リポジトリルートに `.nojekyll` を追加
- [x] `npm install` を実行し、`npm run lint` / `npm run typecheck` が通ることを確認
      (`tsc`は対象ファイルが1つもないとエラーになるため、`js/main.js`をプレースホルダーとして先行作成した)

**完了条件**: 空のプロジェクトに対して lint・typecheck が正常終了する

      (Playwright(Chromium)で自動確認。`playwright install chromium` と
      `playwright install-deps chromium` の実行が別途必要だった)

**完了条件**: 静的な画面(地図・グラフはまだ空でよい)がエラーなく表示される

- [x] 「リセット」ボタンで全マーカー・線を削除する

      `route.waypoints` に経由地点が正しく追加/削除されることをコンソールログ等で確認する
      (Playwrightで地図クリック・1つ戻す・リセットを自動操作し、マーカー数・線の数・
      ボタンの有効/無効・コンソールログを確認した)

**完了条件**: requirements.mdの「地図クリックでマーカー追加」「1つ戻す」「リセット」の項目を満たす

## 3. 区間補間(RouteSampler)

- [x] `js/routeSampler.js` を作成し、2点間を50m間隔で補間して `RoutePoint[]`(elevation: null)を生成する関数を実装
- [x] `main.js` から、追加された区間のみを渡して呼び出し、`route.points` に反映する
- [x] 地図上に補間点自体は描画しないことを確認する
      (Playwrightで約106km離れた2点をクリックし、`route.points`が2128点(約50m間隔相当)に
      増える一方、地図上のマーカーは経由地点の2個のままであることを確認した。
      1つ戻す/リセットで補間点も正しく切り詰められることもあわせて確認した)

**完了条件**: 経由地点を2つ置いたとき、`route.points` に距離50m間隔の点が生成される(デバッグ表示等で確認)

## 4. 標高取得(ElevationService)

- [x] `js/elevationService.js` を作成
  - [x] 緯度経度→タイル座標・ピクセル位置への変換関数
  - [x] タイル画像の取得・デコード(`crossOrigin="anonymous"` + canvas + `getImageData`)
  - [x] ピクセル値→標高値の変換式の実装
  - [x] 5A→5B→10Bのフォールバック処理
  - [x] 周囲4ピクセルの双線形補間(無効値を除外する処理を含む)
  - [x] タイルのメモリキャッシュ(`Map`)
  - [x] 同時取得数を6に制限するキュー
- [x] `main.js` から `route.points` の該当区間を渡し、非同期で標高を取得・反映する
      (取得結果は`RoutePoint`オブジェクトを直接書き換える方式。世代番号方式は不具合があり
      不採用とした。design.md「世代番号を使わない理由」を参照)
- [x] 既知の地点(例: 富士山山頂付近の座標)で標高値が概ね妥当であることを手動確認する
      (Playwrightでelevationservice.jsを直接呼び出し、富士山頂(剣ヶ峰付近)で約3771.6m
      (実際の標高3776mに近い)、東京駅で約3.6mを確認)
- [x] 海上の座標でも例外で落ちず、`elevation: null` になることを確認する
      (日本列島から離れた太平洋上の座標でnullを確認。404はフォールバック時の想定内の挙動)

**完了条件**: requirements.mdの「地点間の起伏が断面図に反映される」「対象外エリアでエラーにならない」の前提となる標高データが取得できる

## 5. 距離・獲得標高の計算(DistanceCalculator)

- [x] `js/distanceCalculator.js` を作成
  - [x] Haversine公式による2点間距離・累積距離・総距離の計算
  - [x] 標高の平滑化(前後100m移動平均、nullを除外)
  - [x] 閾値3mによる上り/下り判定と `totalAscent` / `totalDescent` の計算
  - [x] 区間ごとの上り/下り(`"up"`/`"down"`)判定データの生成
- [x] `main.js` から標高取得後に呼び出し、`route` を更新する
      (「1つ戻す」時も再計算する。`smoothedElevations`/`segmentDirections`はRoute型に含めず、
      ElevationChart用の付随データとしてmain.js内に保持する)

**完了条件**: 平坦なルートでノイズによる過大な獲得標高が出ないことを手動確認する
(東京湾岸の埋立地で約3.5kmの区間をテスト。平滑化・閾値判定なしでは獲得標高約10m・
下降量約13mになるところ、実装した計算では獲得標高0m・下降量約3.2mに収まることを確認した)

## 9. 結合確認・性能確認

- [x] 一連の操作(クリック連打、1つ戻す、リセットの組み合わせ)を通しで確認する
      (Playwrightで15回の連打+1つ戻す×3+追加クリック×2を行い、期待通りのマーカー数(15)に

      実機のSafari/Edgeそのものでは未検証)
- [x] ブラウザコンソールにエラーが出ないことを確認する
