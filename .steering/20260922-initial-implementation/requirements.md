# 初回実装 要求内容

## 1. 目的

`docs/product-requirements.md` の「高(初期実装)」機能を実装し、
第三者がGitHub Pages上のURLにアクセスして、地図クリックでルートを作成し、
標高断面図とサマリーを得られる状態にする(プロダクトの「成功の定義」を満たす)。

## 2. 今回の実装範囲

### 対象とする機能

| # | 機能 | 参照 |
|---|---|---|
| 1 | 地図表示(国土地理院 地図タイル、Leaflet)と、クリックによる経由地点の追加 | PRD 機能1 |
| 2 | 「1つ戻す」(直前の経由地点の削除)・「リセット」(ルート全体の削除) | PRD 機能要件 |
| 3 | 経由地点間の補間(サンプリング間隔50m) | PRD 機能2 |
| 4 | 国土地理院DEMタイルからの標高取得(5A→5B→10Bの順でフォールバック、双線形補間、タイルキャッシュ) | PRD 機能2 |
| 5 | 標高の平滑化(窓幅200m)と、閾値(3m)による獲得標高・累積下降量の計算 | PRD 機能要件 |
| 6 | 断面図の描画(Chart.js、横軸: 累積距離 / 縦軸: 標高、上り/下りの2色で色分け) | PRD 機能3 |
| 7 | サマリー表示(総距離・総上り・総下り) | PRD 機能4 |
| 8 | 標高の取得中表示と、削除された区間の取得結果が反映されないようにする対策 | 機能設計書「非同期処理と操作の競合」 |

## 3. ユーザーストーリー

1. サイクリストとして、まだ走ったことのないコースを地図上でクリックしてルートを作り、
   標高断面図を見たい。そうすることで、GPXファイルがなくても候補コースのアップダウンを事前に検討できる。
2. サイクリストとして、断面図上で上り区間と下り区間を色分けして見たい。
   そうすることで、どこで脚を使うべきか事前にイメージできる。
3. サイクリストとして、ルートの総距離・総上り・総下りを数値で確認したい。
   そうすることで、コース全体の負荷を比較・判断できる。
4. サイクリストとして、置き間違えた地点を取り消したり、最初から作り直したりしたい。
   そうすることで、試行錯誤しながらコースを検討できる。

## 4. 受け入れ条件

### 機能

- [ ] 地図上をクリックすると経由地点のマーカーが追加され、経由地点間が線で結ばれる
- [ ] 経由地点が2つ以上になると、断面図とサマリーが表示・更新される
- [ ] 断面図の横軸が累積距離(km)、縦軸が標高(m)である
- [ ] 経由地点間の起伏(峠・谷)が断面図に反映される
  (例: 峠をはさんだ2地点だけをクリックしても、峠の盛り上がりが表示される)
- [ ] 上り区間と下り区間が異なる色で表示される
- [ ] 平坦な道(例: 河川敷のサイクリングロード)で、獲得標高がノイズによって過大に計上されない
- [ ] 「1つ戻す」で直前の経由地点が削除され、断面図・サマリーが更新される
- [ ] 「リセット」でルートがすべて削除され、断面図・サマリーが初期状態に戻る
- [ ] 標高の取得中に「1つ戻す」「リセット」を押しても、削除した区間や以前のルートが表示されない
- [ ] 標高の取得中であることが画面上で分かる
- [ ] 海上などデータのない地点を含めても、エラーで止まらず、対象外である旨が通知される
- [ ] 画面上に国土地理院の出典が表示されている

### 性能(PCブラウザ、一般的な光回線)

- [ ] 地図クリックから経由地点のマーカー表示まで100ms以内
- [ ] 取得済みタイルの範囲で区間を追加したとき、断面図・サマリーの更新が1秒以内
- [ ] 100km程度のルートの初回表示が10秒以内

### 品質・公開

- [ ] `npm run lint` と `npm run typecheck` がエラーなく完了する
- [ ] ブラウザのコンソールにエラーが出ない
- [ ] 最新版のChrome / Safari / Firefox / Edgeで動作する
- [ ] GitHub Pages上の公開URLで上記の機能が動作する

## 5. 制約事項

- ビルドツール・フレームワーク・CSSフレームワークは使わない(プレーンHTML/CSS/JS)
- 外部ライブラリ(Leaflet・Chart.js)はCDNから、バージョン固定・SRI付きで読み込む
- 外部通信は国土地理院のタイル取得のみとし、APIキーやサーバーサイド処理は使わない
- 国土地理院サーバーへの負荷に配慮し、タイルのキャッシュと同時取得数の上限(6件)を守る
- GitHub Pagesの公開設定(リポジトリのSettings画面での設定)は、リポジトリ所有者が行う必要がある
