# 技術仕様書

## 1. テクノロジースタック

初めてのWeb開発であること、GitHub Pagesでの静的公開を前提としていることから、
ビルドツールを使わない「プレーンJS/HTML/CSS」構成とし、できるだけシンプルに保つ。

| 種別 | 採用技術 | 理由 |
|---|---|---|
| マークアップ | HTML5 | 標準技術。特別な理由がない限りシンプルな構成にする |
| スタイル | CSS3(素のCSS) | ビルドツール不要。フレームワークは導入しない |
| ロジック | JavaScript(ES2015以降、モダンブラウザのネイティブ機能のみ) | トランスパイル不要。`<script type="module">` でファイル分割 |
| 地図表示 | Leaflet(CDN読み込み) | 軽量・APIキー不要・タイルレイヤーの切り替えが容易 |
| 地図タイル | 国土地理院タイル | APIキー不要、標高データとの一貫性、日本国内特化で見やすい |
| 標高取得 | 国土地理院 標高API | APIキー不要、地図タイルと同一提供元 |
| グラフ描画 | Chart.js(CDN読み込み) | 軽量でドキュメントが豊富、折れ線グラフの色分けが容易 |
| GPXパース(次期) | 標準のDOMParser(XMLとして解析) | 追加ライブラリ不要 |
| ホスティング | GitHub Pages | 無料の静的ホスティング、リポジトリと直結 |
| バージョン管理 | Git / GitHub | ソース管理・公開の両方を兼ねる |

**方針:** npm/ビルドツール(Vite等)やフレームワーク(React等)は導入しない。
ライブラリはすべてCDN経由の `<script>` タグで読み込み、`git push` するだけで
GitHub Pagesに反映される状態を保つ。

## 2. 開発ツールと手法

- エディタ: 制約なし(VS Code等、任意)
- バージョン管理: Git(GitHubリポジトリ)
- デプロイ方法: GitHub Pages(リポジトリの `main` ブランチ、または `/docs` フォルダ・
  `gh-pages` ブランチをGitHub Pagesの公開元として設定)
- ローカル確認: ブラウザで `index.html` を直接開くか、簡易HTTPサーバー
  (例: VS Codeの「Live Server」拡張機能、または `python -m http.server`)を利用
- リント: 必須ツールは導入しないが、ブラウザのコンソールエラーがないことを都度確認する
- テスト: 自動テストは本フェーズでは導入せず、手動での動作確認を基本とする
  (将来的に必要になれば `development-guidelines.md` で追記検討)

## 3. 技術的制約と要件

- **サーバーサイドを持たない**: GitHub Pagesの静的ホスティングのみで完結させる
- **APIキー不要な外部サービスのみ利用**: 国土地理院の地図タイル・標高APIはAPIキー不要で
  CORSにも対応しているため、フロントエンドのJavaScriptから直接呼び出せる
- **対応エリアは日本国内限定**: 国土地理院データの提供範囲に依存する
- **出典表示の義務**: 地図タイル・標高データともに国土地理院のクレジット表示が必要
  (画面のフッター等に明記する)
- **標高APIの一括取得制限**: 国土地理院の標高APIは基本的に1地点ずつの取得となるため、
  クリック地点数が多い場合は逐次リクエスト(場合によっては簡易なリクエスト間隔調整)を
  実装し、サーバー負荷や取得漏れに配慮する
- **ブラウザ対応**: 最新版のChrome / Safari / Firefox / Edgeを対象とし、
  古いブラウザ(IE等)は対象外とする

## 4. パフォーマンス要件

- 地図クリックによるルート作成では、クリックのたびに1地点ずつ標高を取得するため、
  瞬間的に大量のリクエストが発生することはない
- (次期)GPX読み込み時は、ファイルに数百〜数千のトラックポイントが含まれる場合があり、
  それらを一度に標高取得しようとするとリクエストが集中する。その場合は必要に応じて
  一定間隔でのポイント間引き・簡略化や、リクエストの分割送信を検討する
- 地図操作(パン・ズーム・クリック)がもたつかないよう、地図上の描画要素(マーカー・線)は
  必要最小限に留める
- 断面図の再描画は、ルート変更のたびに行うが、極端な描画遅延が発生しないようデータ量に
  応じた最適化(間引き等)を行う
