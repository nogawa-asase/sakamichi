# プロダクト要求定義書

## 1. プロダクトビジョンと目的

サイクリストが走行予定のルートの「上り・下り」を事前に視覚的に把握できる、
標高断面図表示Webサービスを提供する。地図上にルートをクリックして入力するだけで、
ルートの累積距離に対する標高変化をグラフとして即座に確認できるようにし、
ライド計画時の負荷予測・コース選定を支援する。

- 公開範囲: インターネット上で誰でも利用可能な静的Webサービス(GitHub Pages)
- 対象エリア: 日本国内(国土地理院の標高データを利用)

## 2. ターゲットユーザーと課題・ニーズ

### ターゲットユーザー
- サイクリスト(ロードバイク・グラベルバイク等で長距離ライドを計画する層)

### 課題・ニーズ
- まだ走ったことのないコースを、地図を見ながら候補として検討したい
  (この段階ではGPXファイルはまだ持っていない)
- 候補ルートの獲得標高やアップダウンの位置・傾斜感を、事前に視覚的につかみたい
- 曲がりくねった山道や最大100km程度の長距離ルートでも正確に断面を見たい
- 専用アプリのインストールや会員登録なしに、ブラウザだけで手軽に使いたい
- (次期)すでに手元にGPXファイル(Stravaやサイコンからのエクスポート等)がある場合は、
  それを読み込んで同様に断面を確認したい

## 3. 主要な機能一覧

| # | 機能 | 優先度 |
|---|------|--------|
| 1 | 地図クリックによるルート入力 | 高(初期実装) |
| 2 | 国土地理院DEMタイルを用いた標高取得(地点間の補間を含む) | 高(初期実装) |
| 3 | 累積距離×標高の断面図表示(上り/下り) | 高(初期実装) |
| 4 | 総距離・獲得標高・累積下降量のサマリー表示 | 高(初期実装) |
| 5 | GPXファイルの読み込み・パース | 中(次期実装) |

## 4. 成功の定義

- 自分以外の第三者(サイクリスト)が、インターネット経由でこのツールにアクセスし、
  地図上にルートをクリックして入力し、断面図を得られる状態を「成功」とする
- インストール不要・登録不要で、GitHub Pages上のURLにアクセスするだけで使える

## 5. ビジネス要件

- 個人開発・非商用の公開ツールとして提供する
- サーバーサイド処理・自前バックエンドは持たない(GitHub Pagesの静的ホスティングのみ)
- 外部リソースは国土地理院のタイル(地図タイル・DEMタイル)のみを利用し、追加コストを発生させない

## 6. ユーザーストーリー

1. サイクリストとして、まだ走ったことのないコースを地図上でクリックしてルートを作り、
   標高断面図を見たい。そうすることで、GPXファイルがなくても候補コースの
   アップダウンを事前に検討できる。
2. サイクリストとして、断面図上で上り区間と下り区間を色分けして見たい。
   そうすることで、どこで脚を使うべきか事前にイメージできる。
3. (次期)サイクリストとして、手元にGPXファイルがある場合はそれをアップロードするだけで、
   同様に標高断面図を見たい。そうすることで、既存のルートデータも活用できる。

## 7. 受け入れ条件

- 地図上をクリックして地点を追加していくと、エラーなくルートが作成され断面図が描画されること
- 最長100km程度、曲がりくねったルートでも、「9. 非機能要件」の性能目標を満たすこと
- 平坦な道で、DEMのノイズにより獲得標高が過大に計上されないこと
- 断面図の横軸が累積距離、縦軸が標高であること
- クリックした地点と地点の間も一定間隔で標高が取得され、地点間の起伏(峠・谷)が断面図に反映されること
- 標高値は国土地理院DEM(5mメッシュ優先、欠損時は10mメッシュ)から取得した値であること
- GitHub Pages上(静的ホスティング)で全機能が動作すること
- (次期)GPXファイル(トラックポイントに緯度経度を含むもの)をアップロードした場合も、
  同様にエラーなく断面図が描画されること

## 8. 機能要件

- 地図上でのクリックによる地点追加(ルート作成)、直前の地点の削除、ルートのリセット
- クリックした地点間を直線で結び、一定のサンプリング間隔(初期値50m)で補間点を生成
- 国土地理院のDEMタイルから、クリック地点および補間点の標高を取得
- 各区間の水平距離計算(Haversine公式)による累積距離の算出
  (地点間は直線で結ぶため、道路に沿った距離ではない)
- 標高の平滑化(移動平均)と、閾値による上り/下りの判定(ノイズによる過大計上の防止)
- 累積距離×標高のラインチャート描画(上り/下りの色分け表示)
- 総距離・獲得標高・累積下降量のサマリー表示
- 標高の取得中であることの表示
- (次期)GPXファイルのアップロード(ドラッグ&ドロップ、またはファイル選択)
- (次期)GPXのトラックポイント(緯度・経度、可能であれば標高)のパース、
  および標高が含まれない場合の国土地理院データによる補完

## 9. 非機能要件

- 静的ホスティング(GitHub Pages)のみで完結し、サーバーサイド実装を持たないこと
- 対応エリアは日本国内に限定してよい
- 性能目標(PCブラウザ、一般的な光回線を想定):

  | 操作 | 目標 |
  |---|---|
  | 地図クリックから経由地点のマーカー表示まで | 100ms以内 |
  | 取得済みタイルの範囲で区間を追加したときの断面図・サマリー更新 | 1秒以内 |
  | 100km(サンプリング間隔50mで約2,000点)のルートの初回表示 | 10秒以内 |

- 標高の取得に時間がかかる場合も、取得中であることが画面上で分かること
- (次期)多数のトラックポイントを含むGPXでも同様に処理できること
- モダンブラウザ(最新版のChrome/Safari/Firefox/Edge)で動作すること
- レスポンシブ対応は必須ではないが、PCブラウザでの利用を主軸に想定する

## 10. 既知の制約

- 経由地点間は直線で結ぶため、距離・断面は道路に沿ったものではない
  (実際の道路に近づけるには、経由地点を細かく置く必要がある)
- DEMは地表面の標高であるため、**トンネル**区間は山を越えるような断面に、
  **橋**の区間は谷へ下るような断面になる
- 標高の平滑化により、ごく短い急坂は実際より緩やかに表示される場合がある
