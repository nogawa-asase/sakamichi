# 開発ガイドライン

初めてのWeb開発であることを踏まえ、複雑なルールは設けず、
「読みやすさ」「シンプルさ」を最優先したガイドラインとする。

## 1. コーディング規約

- ビルドツール・トランスパイラは使わないため、モダンブラウザがそのまま実行できる
  JavaScript(ES2015以降の構文)のみを使用する
- 各JSファイルは `docs/repository-structure.md` で定義したモジュール単位を守り、
  1ファイルが長くなりすぎないようにする(目安: 200〜300行を超えたら分割を検討)
- `var` は使わず、`const` / `let` を使う(再代入しない変数は `const` を基本とする)
- 関数・変数には必ず意味のある名前をつけ、省略しすぎない(例: `calcDist` ではなく
  `calculateDistance`)
- グローバル変数は極力作らず、`<script type="module">` によるモジュールスコープを活用する
- 関数の引数・戻り値や、データモデル(`Waypoint`・`RoutePoint`・`Route`)にはJSDocで型注釈を付け、
  型チェック(`tsc --noEmit`)を通す
- 外部リソース(国土地理院タイル)の取得は必ず `try/catch` でエラーハンドリングし、
  失敗時にユーザーへ分かりやすいメッセージを表示する
- マジックナンバー(意味不明な数値の直接記述)は避け、定数として名前をつける
  (例: `const EARTH_RADIUS_M = 6371000;`)

### リント・型チェック

- コード変更後は必ず以下を実行し、エラーがない状態でコミットする
  - `npm run lint` (ESLint)
  - `npm run typecheck` (TypeScriptによる型チェック。JSファイルは生成しない)
- 初回のみ `npm install` で開発用ツールをインストールする

## 2. 命名規則

| 対象 | 規則 | 例 |
|---|---|---|
| JavaScript変数・関数 | camelCase | `routePoints`, `calculateDistance()` |
| JavaScriptクラス(使う場合) | PascalCase | `ElevationChart` |
| 定数 | UPPER_SNAKE_CASE | `EARTH_RADIUS_M` |
| CSSクラス | kebab-case | `.map-container`, `.summary-panel` |
| ファイル名(JS/CSS) | camelCase(JS)/kebab-case(CSS) | `elevationChart.js`, `style.css` |
| HTML id属性 | kebab-case | `id="elevation-chart"` |

## 3. スタイリング規約

- Tailwind等のCSSフレームワークは導入せず、素のCSSで記述する
- クラス名は役割が分かる名前にする(見た目ではなく用途で命名する。
  例: `.button-danger` ではなく `.reset-button`)
- レイアウトは基本的にFlexbox/Gridを使用し、複雑な独自計算配置は避ける
- 色・余白などの繰り返し使う値は、CSSカスタムプロパティ(`:root { --main-color: ... }`)
  として定義し、直接値を書き散らさない

## 4. テスト規約

- 本フェーズでは自動テストフレームワークは導入しない
- 機能追加・修正のたびに、簡易HTTPサーバー経由でページを開き、以下を手動で確認する
  - ブラウザのコンソールにエラーが出ていないこと
  - 地図クリックでルートが正しく作成されること
  - 経由地点間の起伏(峠・谷)が断面図に反映されること
  - 断面図・サマリーが期待通り更新されること
  - GitHub Pagesへの反映後も同様に動作すること
  - 標高の取得中に「1つ戻す」「リセット」を押しても、削除した区間や以前のルートが表示されないこと
- Claude Codeによる作業では、Playwright(Chromium)でブラウザを操作し、上記の確認を補助してよい
  (正式な自動テストとしては扱わない)
- 自動テストの導入が必要になった場合は、本ドキュメントを更新して方針を追記する

## 5. Git規約

- ブランチ運用: 個人開発のため、基本は `main` ブランチへの直接コミットで問題ないが、
  大きめの機能追加時は `feature/[機能名]` ブランチを切ってから `main` にマージしてもよい
- コミットメッセージ: 日本語でよい。「何を」「なぜ」変更したかが分かる一文を書く
  (例: `地図クリックでルートを作成できるようにする`)
- コミット単位: 動作する単位でこまめにコミットする(1コミット=1つの意味のある変更)
- `.steering/[YYYYMMDD]-[開発タイトル]/` の作成・更新もコードと合わせてコミットする
